# Как редактировать уровни

Руководство для владельца проекта: как самому двигать платформы, менять
ловушки, добавлять новые объекты и проверять, что ничего не сломалось.

Кода писать не придётся — уровень в этом проекте это **список чисел**, а не
программа. Всё, что ниже, сводится к «открой файл, найди строку, поменяй
число, запусти проверку».

---

## 1. Что такое уровень в этой игре

Один уровень — **ровно один экран**. Камера никогда не едет. Игрок видит всю
геометрию, все ловушки и выход с точки старта, ещё не сделав ни шага.

- Ширина: **48 клеток**, высота: **27 клеток**. Всегда. Менять нельзя.
- Одна клетка = 10 пикселей.
- Сложность берётся из расстановки и точности, а не из длины. Уровень
  проектируется **вверх**, а не вбок (`CLAUDE.md` #2).

Уровней 60: 10 секторов по 6 — кампания собрана полностью.

## 2. Система координат — самое важное

```
      col →  0    5    10   15   20   25   30   35   40   45  47
row 0      ┌──────────────────────────────────────────────────┐  ← потолок
 ↓         │                                                  │
row 5      │                                                  │
row 10     │                  чем МЕНЬШЕ row,                  │
row 15     │                  тем ВЫШЕ на экране               │
row 19     │      ▓▓▓▓▓  ← платформа  { col: 6, row: 19, width: 5 }
row 22     ├██████████████████████████████████████████████████┤  ← groundRow
row 23     │██████████████ земля до самого низа ██████████████│
row 26     └──────────────────────────────────────────────────┘
```

Два правила, которые ломают новичкам всё:

1. **`row` растёт ВНИЗ.** `row: 10` — высоко в воздухе. `row: 22` — уровень
   земли. Чтобы поднять платформу выше, число надо **уменьшить**.
2. **`col` и `row` — это клетка, а не пиксель.** Игра сама умножает на 10.

`groundRow: 22` — земля начинается на 22-й строке и залита до самого низа.
Почти во всех уровнях это 22; менять без причины не стоит.

**Платформы односторонние:** снизу игрок проходит сквозь них, сверху — стоит.
Это важно при проектировании подъёмов: под платформу можно запрыгнуть, и она
не помешает.

## 4. Анатомия уровня

Ниже — учебный пример: он собран из **всех** полей сразу, чтобы показать
каждое. В настоящем уровне лишние поля просто отсутствуют (например, у
`PATROL` нет ни ям, ни статичных шипов).

```ts
{
  id: 'sector-01-level-03',      // менять нельзя — по нему считается прогресс
  name: 'PATROL',                // имя на экране
  width: 48,                     // всегда 48
  groundRow: 22,                 // уровень земли

  gaps: [[12, 14]],              // ямы: от колонки 12 до 14 включительно
  spikeColumns: [8, 9],          // статичные шипы на земле, в колонках 8 и 9
  platforms: [                   // висящие платформы
    { col: 26, row: 19, width: 5 },
  ],

  playerStartCol: 2,             // где появляется игрок (стоит на земле)
  exitCol: 43,                   // выход занимает колонки 43 и 44
  exitRow: 13,                   // (необязательно) на какой поверхности стоит
                                 //  выход. Без этой строки — на земле.

  starTimeMs: 9000,              // (необязательно) целевое время третьей
                                 //  звезды. Без этой строки считается само.

  traps: [                       // всё динамическое (раздел 6 и 7)
    ...dropSpike('dspike-01', 34, 21, 22),
    { type: 'laser', id: 'laser-01', col: 30, topRow: 16, bottomRow: 21 },
  ],
}
```

Для сравнения — как `PATROL` выглядит на самом деле: `gaps: []`,
`spikeColumns: []`, две платформы `{ col: 16, row: 19, width: 5 }` и
`{ col: 26, row: 19, width: 5 }`, `exitCol: 43` без `exitRow` (значит, выход
стоит на земле).

Несколько тонкостей:

- `gaps` — **включительные** диапазоны. `[12, 14]` это три пустые колонки:
  12, 13 и 14.
- `spikeColumns` — только на земле. Шипы на платформе делаются ловушкой
  (`spike-bank`), а не здесь.
- `platforms` — `col` это **левый край**, `row` — строка, по которой ходят,
  `width` — сколько клеток вправо.
- `exitCol` занимает **две** колонки: `exitCol` и `exitCol + 1`.
- `exitRow` обязан быть настоящей поверхностью: землёй или платформой.
  Выход, висящий в воздухе, не пройдёт проверку.
- `starTimeMs` **почти никогда не нужно писать руками** — см. раздел 4.1.

### 4.1. Звёзды и целевое время

У каждого уровня три звезды:

| Звезда | За что |
|---|---|
| ★ | уровень пройден |
| ★★ | пройден без единой смерти |
| ★★★ | без смертей **и** уложился в целевое время |

**Целевое время считается само, из геометрии уровня.** Игра берёт тот самый
маршрут, которым солвер доказывает проходимость, проходит по нему физикой
(бег `110 px/с`, настоящие дуги прыжков) и получает «пол» — время, которое
не побить никак. Дальше прибавляется допуск на ожидание таймингованных
ловушек, попавших на маршрут, и всё это умножается на запас 2.4 «на живого
человека». Подвинешь платформу — цель подвинется вместе с ней.

Поэтому `starTimeMs` нужен ровно в одном случае: **расчёт ошибся про темп
конкретного уровня, и ты это увидел, играя**. Например, окно ловушки
открывается раз в четыре секунды на единственном уступе, где имеет смысл
стоять, — геометрия этого не видит.

Как посмотреть расчётное значение по всем уровням:

```sh
pnpm levels
```

Цель печатается рядом с вердиктом проходимости.

Ограничение одно, и оно проверяется тестом: **цель не может быть ниже пола**.
Поставишь меньше — `pnpm test` покажет красное и назовёт уровень. Это защита
от третьей звезды, которую физически нельзя получить.

## 5. Что игрок реально может достать прыжком

Это главное практическое ограничение. Все числа посчитаны из физики игры,
а не подобраны на глаз (`src/gameplay/jumpPhysics.ts`).

| Подъём (клеток вверх) | Максимальная длина прыжка |
|---|---|
| 0 (на той же высоте) | **5.7 клетки** |
| 1 клетка вверх | 5.3 клетки |
| 2 клетки вверх | 4.8 клетки |
| 3 клетки вверх | **4.0 клетки** |
| 4 клетки вверх | **невозможно** |

Практические выводы:

- **Максимальный подъём за один прыжок — 3 клетки.** Разница в 4 строки между
  платформами непроходима, всегда.
- Стандартный шаг лестницы в этой игре — **3 строки вверх и 3-8 колонок
  вбок**. Так построены почти все подъёмы.
- Чем выше прыгаешь, тем короче достаёшь. Подъём на 3 строки + сдвиг на 5
  колонок уже не проходит (максимум 4.0).
- Яма шире **5 колонок** непроходима с разбега по ровной земле.

Числа — нижняя граница (реальный прыжок может чуть-чуть больше), поэтому
проектировать лучше с запасом в полклетки.

## 6. Каталог объектов

Всё, что можно поставить в `traps`. У каждого объекта обязательно есть
**уникальный в пределах уровня `id`** — по нему на объект ссылаются триггеры.

### Шипы и убивающее

**`moving-spike`** — шип, который бесконечно ездит туда-обратно. Всегда
видим, всегда смертелен; его движение и есть предупреждение.

```ts
{ type: 'moving-spike', id: 'mspike-01', fromCol: 34, fromRow: 21, toCol: 40, toRow: 21, travelMs: 2400 }
```
`travelMs` — сколько миллисекунд занимает путь в одну сторону. Больше =
медленнее.

> **Правило:** такой шип можно ставить либо **на одну строку выше
> поверхности** (препятствие, которое перепрыгивают), либо **выше роста
> игрока целиком** (декорация). Между этими вариантами — стена посреди
> коридора, и тест это запретит.

**`spike-bank`** — поршень: полоса шипов, которая выезжает из пола (или
потолка) по честному циклу.

```ts
{ type: 'spike-bank', id: 'sbank-01', col: 14, width: 3, hiddenRow: 23, lethalRow: 21 }
```
- `hiddenRow` **ниже** `lethalRow` → выезжает из пола вверх.
- `hiddenRow` **выше** `lethalRow` → падает с потолка вниз (текстура
  переворачивается автоматически).
- `width` — сколько колонок он занимает.

**`spike-wall`** — шипы, выезжающие вбок и запирающие проход. Перепрыгнуть
нельзя, только не находиться в проёме.

```ts
{ type: 'spike-wall', id: 'swall-01', col: 12, topRow: 19, bottomRow: 21, extendTiles: 4, fromRight: false }
```

**`orbit-spike`** — шип на вращающемся рычаге, крутится с постоянной
скоростью.

```ts
{ type: 'orbit-spike', id: 'orbit-01', pivotCol: 33, pivotRow: 16, radiusTiles: 1.75, periodMs: 2000 }
```
Радиус — в клетках, от центра. Зона, которую он накрывает: `pivotCol ±
radiusTiles` по горизонтали и `pivotRow ± radiusTiles` по вертикали.

**`swinging-spike`** — маятник: качается по дуге и видимо тормозит на
краях.

```ts
{ type: 'swinging-spike', id: 'swing-01', pivotCol: 31, pivotRow: 4, lengthTiles: 4, maxAngleDeg: 44, periodMs: 1600 }
```

**`loop-spike`** — шип, идущий по замкнутому маршруту в одну сторону.

```ts
{
  type: 'loop-spike', id: 'loop-01', travelMs: 1150,
  waypoints: [ { col: 14, row: 17 }, { col: 20, row: 17 }, { col: 20, row: 20 }, { col: 14, row: 20 } ],
}
```

**`laser`** — вертикальный луч, включается и выключается по циклу.

```ts
{ type: 'laser', id: 'laser-01', col: 30, topRow: 16, bottomRow: 21, initialIdleMs: 700 }
```

**`electric-floor`** — участок пола, который периодически бьёт током. В
спокойной фазе неотличим от обычного пола.

```ts
{ type: 'electric-floor', id: 'ef-01', col: 13, width: 6, row: 22,
  timing: { idleMs: 1200, warningMs: 500, activeMs: 500, cooldownMs: 250 } }
```

**`pursuer`** — красный шар, который летит за игроком. Никогда не быстрее
игрока.

```ts
{ type: 'pursuer', id: 'pursuer-01', col: 5, row: 21, speedFactor: 0.75, startDelayMs: 2000 }
```
`speedFactor` — доля от скорости игрока. **Всегда меньше 1.**

### Платформы и пол

**`falling-platform`** — плита, которая падает, когда на неё наступают.
Выглядит как обычная.

```ts
{ type: 'falling-platform', id: 'flp-01', col: 19, row: 19, width: 3 }
```

**`disappearing-platform`** — плита, которая крошится под ногами и через
время возвращается.

```ts
{ type: 'disappearing-platform', id: 'dp-01', col: 29, row: 16, width: 3, crumbleMs: 350, goneMs: 1500 }
```

**`fake-platform`** — фантом: выглядит точь-в-точь как настоящая плита, но
сквозь неё проваливаешься.

```ts
{ type: 'fake-platform', id: 'fakep-01', col: 28, row: 16, width: 4 }
```

> **Правило:** под фантомом не может быть ямы или смертельной ловушки. Только
> обычная земля — или статичные шипы (`spikeColumns`), которые видно с самого
> старта. Иначе это невидимое убийство, и тест не пропустит.

**`moving-platform`** — платформа, которая ездит между двумя точками.

```ts
{ type: 'moving-platform', id: 'movp-01', fromCol: 16, fromRow: 22, toCol: 21, toRow: 22, width: 13, travelMs: 2400 }
```

**`launch-pad`** — катапульта. **Единственный объект в игре, который тебе
помогает, а не мешает.** Твёрдая поверхность: на ней можно стоять, по ней
можно ходить и с неё можно прыгать. Раз в цикл она выстреливает и подбрасывает
того, кто на ней стоит, — выше, чем достаёт любой прыжок.

```ts
{ type: 'launch-pad', id: 'pad-01', col: 19, row: 22, width: 3, liftTiles: 8 }
```

- `liftTiles` — на сколько тайлов подбрасывает. **Больше 9 ставить нельзя**:
  тело игрока ограничено `maxFallSpeed`, и всё, что выше, молча срезается.
- **Реально доступно меньше номинала примерно на треть тайла** — за первый
  кадр гравитация успевает отнять своё. Солвер считает по реальному числу, а
  не по номиналу, поэтому уступ на 8 тайлов при `liftTiles: 8` он **не**
  засчитает. Ставь катапульту с запасом.
- `loop: false` делает её одноразовой, по триггеру. Тогда солвер перестаёт
  считать её способом подняться (выстрела может не случиться вовсе) — но
  поверхностью она остаётся.
- Выстрел предупреждает, как любая таймингованная ловушка: стрелка мигает всю
  фазу `warning`. Это не украшение — подбросить без предупреждения прямо в шип
  значит убить без возможности среагировать.
- **Солвер согласен ≠ играется.** Он меряет предельный охват при идеальном
  управлении с первого кадра. На `CROSSING` перелёт «70 px разрыва против 79
  доступных» солвер подписал, а живьём андроид улетел в яму — потому что
  запуск был не с крайней плитки катапульты, а с середины. Если запас меньше
  тайла-двух, это не уровень, а лотерея: клади посадку ближе или добавь
  подброса.
- `initialIdleMs` сдвигает первый выстрел — этим катапульта расходится по
  фазе с ловушкой того же периода. Работает с 2026-09-19: до этого поле
  принималось и молча игнорировалось (логика жила копиями в четырёх других
  классах ловушек, и катапульта её просто не получила).
- **Разные периоды = плывущее окно.** Если у ловушки рядом цикл не кратен
  циклу катапульты, соотношение меняется от выстрела к выстрелу: часть
  запусков чистые, часть смертельные. Это честно, но только пока игрок видит
  обе фазы с плиты и успевает сойти (сектор 07 построен ровно на этом).
- **Две катапульты друг над другом не ставь.** Первый запуск пролетит ярус
  насквозь, приземлится на вторую и тут же швырнёт снова — два запуска на одно
  решение игрока, а ярус между ними ни о чём не спросит. Разноси по колонкам.

**`conveyor`** — движущийся пол. **Не ловушка в обычном смысле: он никогда
не убивает и ничего не предупреждает.** Твёрдая поверхность, на которой
можно стоять и с которой можно прыгать, — она просто тянет стоящего, всегда,
в одну сторону.

```ts
{ type: 'conveyor', id: 'belt-01', col: 12, row: 22, width: 6, speed: 70 }
```

- `speed` — px/с. Плюс тянет вправо, минус влево. **Больше 72 поставить
  нельзя** (у игрока 110): против ленты обязано быть можно идти, иначе
  полоса пола становится стеной, которой солвер не видит — он считает ленту
  обычной опорой. Проверяется `tests/conveyor.test.ts`.
- Убивает не лента, а то, к чему она подносит: яма, луч, плита. У каждого
  из них свой телеграф остаётся на месте.
- Шеврон на плитке прокручивается ровно с той скоростью, с какой лента тянет
  — движение и есть предупреждение, как у патрулирующего шипа.
- Целевое время уже знает про ленту: `parTime.ts` считает ход по ленте и
  против неё по-разному. Замерено вживую: против ленты в 50 px/с игрок реально
  идёт ~86 px/с, расчёт берёт 60 — то есть цель заведомо не жёстче реальности.
- Лента — это опора, и солвер её так и считает. Но подъём она не даёт: тянет
  только того, кто **на земле**, поэтому скорость отрыва в прыжке всегда
  собственная, и вся дальность из §3 остаётся в силе.

### Прочее

**`timing-gate`** — ворота, которые перекрывают проход, но **не убивают**.
Ошибка стоит такта, а не попытки.

```ts
{ type: 'timing-gate', id: 'gate-01', col: 20, topRow: 16, bottomRow: 21 }
```

**`fake-exit`** — обманная дверь. Затягивает вошедшего и возвращает на старт
уровня, таймер не останавливается. Никогда не убивает. **Максимум одна на
сектор.**

```ts
{ type: 'fake-exit', id: 'fake-exit-01', col: 27, row: 22 }
```

**`trigger`** — невидимая зона, которая запускает другую ловушку. Вручную её
почти никогда не пишут — см. следующий раздел.

```ts
{ type: 'trigger', id: 't-01', col: 20, row: 17, width: 3, height: 5, targetId: 'dspike-01' }
```

### Тайминги

У всех циклических ловушек (`laser`, `spike-bank`, `spike-wall`,
`electric-floor`, `timing-gate`) есть необязательное поле `timing`:

```ts
timing: { idleMs: 900, warningMs: 400, activeMs: 700, cooldownMs: 300 }
```

| Фаза | Что происходит |
|---|---|
| `idleMs` | Спокойно, не убивает |
| `warningMs` | Видимое предупреждение, ещё **не** убивает |
| `activeMs` | **Убивает** |
| `cooldownMs` | Возврат в спокойное состояние |

- **`warningMs` нельзя опускать ниже 250.** Это не настройка, а инвариант
  честности (`CLAUDE.md` #4.2). Игра просто откажется запускаться.
- `initialIdleMs` — сдвиг фазы на старте. Так две одинаковые ловушки
  работают не в такт: поставь одной `initialIdleMs: 700`, и уровень нельзя
  будет пройти под один ритм.

## 7. Готовые связки

Большинство «внезапных» ловушек — это на самом деле **пара**: сама ловушка
плюс невидимый триггер, который её запускает. Считать размер и положение
триггера вручную не нужно и не надо — для этого есть готовые функции из
`ambush.ts`. Они ставят триггер ровно туда, где игрок успевает среагировать.

**Падающий сверху шип:**
```ts
...dropSpike('dspike-01', 34, 21, 22)
//            id          │   │   └─ поверхность, по которой бежит игрок
//                        │   └───── строка, куда шип падает
//                        └───────── колонка шипа
```

**Шипы, выскакивающие из пола:**
```ts
...floorSpikes('sbank-01', 38, 3, 22)
//              id          │   │  └─ поверхность
//                          │   └──── ширина в клетках
//                          └──────── левая колонка
```

**Люк (пол проваливается):**
```ts
...trapdoor('flp-01', 12, 3)
//           id        │   └─ ширина
//                     └───── левая колонка
```
Важно: яму под люком нужно **отдельно** объявить в `gaps` того же уровня —
её читает солвер проходимости.

**Уезжающая яма:**
```ts
...shiftingPit('sp-01', 37, 34, 3)
//              id       │   │   └─ ширина плиты
//                       │   └───── куда уезжает
//                       └───────── откуда уезжает
```

Три точки `...` перед вызовом обязательны — они «разворачивают» пару
(ловушка + триггер) в список.

Тонкая настройка через последний аргумент:
```ts
...dropSpike('mspike-03', 34, 21, 22, { lead: 5, activeMs: 1000 })
```
- `lead` — за сколько колонок до ловушки стоит триггер. Больше = раньше
  срабатывает = больше времени на реакцию.
- `from: 'right'` — если игрок подходит справа.

## 8. Как проверить, что ничего не сломал

Три команды, в порядке важности. Запускать из папки проекта.

### `pnpm levels` — карта и проходимость

Главный инструмент. Рисует каждый уровень текстом и говорит, проходим ли он.

```
=== sector-01-level-03 · PATROL · solvable
 0|                                                |
...
19|                          #####                 |
21|  P     ^^        tttx        x       EE        |
22|############   #################################|
  |0         1         2         3         4       |
```

Легенда:

| Знак | Что это |
|---|---|
| `#` | земля или платформа |
| `^` | статичный шип |
| `P` | старт игрока |
| `E` | выход |
| `x` | шип-ловушка (любой движущийся) |
| `o` | преследователь |
| `=` | платформа-ловушка (падающая / исчезающая / фантом / едущая) |
| `\|` | лазер или ворота |
| `~` | электропол |
| `t` | триггер |
| `F` | фальшивый выход |

Слово **`solvable`** в заголовке — уровень математически проходим. Если там
`UNSOLVABLE`, правку нужно откатывать: игра не выпускает непроходимые уровни
(`CLAUDE.md` #4.3).

Цифры слева — номера строк, цифры снизу — десятки колонок. По этой картинке
удобно считать расстояния, не запуская игру.


#### Строка «маршрут не проходит рядом»

Под картой может появиться такая строка:

```
    ! маршрут не проходит рядом: laser-02
```

Она значит ровно одно: **по доказанному маршруту тело игрока ни разу не
оказывается там, где эта ловушка может убить.** Проверяется настоящей
баллистикой — та же гравитация 900, та же скорость прыжка −250, тот же
хитбокс 12×32 px, что в игре, — а не «рядом ли колонки».

**Это предупреждение, а не ошибка, и `pnpm levels` от него не падает.**
Причина: трассируется **один** маршрут, тот, которым солвер доказывает
проходимость. У уровня их может быть несколько, и тогда ловушка на другом
пути делает свою работу — на `sector-07-level-02` так и задумано: быстрый
путь под шипами и медленный в обход, и банк на подходе к медленному солвер
не встречает никогда.

Поэтому строка — это вопрос: **что стережёт эта ловушка?** Если ответ
«альтернативный путь» — всё в порядке. Если ответа нет, ловушка висит в
пустоте, и её надо либо передвинуть, либо убрать.

**Зачем это вообще появилось.** 19.09.2026 на `sector-10-level-06` в трёх
тайлах от выхода стоял патрулирующий шип. Уровень был признан проходимым,
все тесты проекта проходили, замер окон опасности его видел — и коснуться
игрока он не мог: прыжок, который он якобы стерёг, проходит над ним в
апогее, хитбокс кончается на y=95, шип начинается на y=110. Пятнадцать
пикселей чистого воздуха, каждую попытку. Нашёл его владелец глазами.

Солвер доказывает, что маршрут **существует**, и ничего не говорит о том,
через что этот маршрут идёт. Проверки ловушек — про правила расстановки
(телеграф, не над ямой, не на колонке выхода), и ловушка в пустоте не
нарушает ни одного. Не хватало самого простого вопроса: **может ли игрок
вообще оказаться там, где эта штука есть.**

И это не «просто лишняя декорация». В игре, весь договор которой — что на
экране, то и правда, ловушка, которая не может коснуться, учит обходить
то, чего нет. Следующая, которую игрок сочтёт декорацией, окажется той,
которая убивает.

### `pnpm test` — правила честности

Около 950 проверок. Из них примерно 630 — про уровни. Они ловят то, что
солвер не видит: шип в недосягаемости, две ловушки на одних клетках, фантом
над ямой.

Если тест упал, он **пишет человеческим текстом, что именно не так** и в
каком уровне. Это не препятствие, а подсказка.

### `pnpm typecheck` — опечатки

Ловит опечатки в названиях полей (`colum` вместо `col`), забытые запятые,
неверный тип ловушки. Запускать первым, если что-то совсем не работает.

### Посмотреть глазами

```
pnpm dev
```
Откроется игра в браузере. Чтобы прыгнуть сразу на нужный уровень, открой
консоль браузера (F12) и вставь:

```js
__game.scene.getScene('GameplayScene')?.scene.stop();
__game.scene.start('GameplayScene', { levelId: 'sector-01-level-03' });
```

Обе строки сразу — первая гасит текущий уровень, вторая запускает нужный.
Работает только в `pnpm dev`, в собранной игре этой лазейки нет.

Клавиша **F3** включает отладочный оверлей: FPS и настоящие хитбоксы всех
объектов — видно, где именно ловушка убивает, а не где нарисована.

## 9. Правила, которые нельзя нарушить

Они не бюрократия — каждое появилось после конкретного бага. Тесты
проверяют их автоматически, так что нарушить незаметно не выйдет.

1. **Уровень всегда проходим.** Проверяет солвер. Падающий пол при этом не
   считается опорой вообще: уровень обязан проходиться, даже если все
   падающие плиты уже упали.
2. **Смертельная угроза предупреждает минимум 250 мс.** Исключения — только
   те, что уже записаны в `CLAUDE.md` #4.2 (падающий пол, люк).
3. **Тупиков не бывает.** Из любой точки должен быть путь дальше или смерть.
4. **Две ловушки не стоят на одних и тех же клетках.** Одну из них
   невозможно прочитать, и выглядит это как сломанный триггер.
5. **Под фантомной платформой — только безопасная земля** (или видимые с
   самого старта статичные шипы).
6. **Никакой случайности.** Никаких случайных чисел в геймплее — всё
   детерминировано.
7. **Фальшивый выход — максимум один на сектор**, всегда с незасвеченным
   ядром, и никогда не смертельный.

Проверочный вопрос после каждой смерти: **«мог ли игрок этого избежать,
зная то, что было видно на экране?»** Если нет — это баг, а не сложность.

## 10. Рецепты

### Подвинуть платформу
Найди её в `platforms`, поменяй `col` (вбок) или `row` (вверх/вниз, меньше =
выше). Проверь по таблице из раздела 5, что до неё всё ещё можно допрыгнуть с
предыдущей. `pnpm levels`.

### Сделать подъём сложнее
Не добавляй ловушку сразу — сначала посмотри на геометрию. Самая частая
причина «слишком легко» — соседние платформы **перекрываются по колонкам**,
и игрок поднимается, просто прыгая вверх на месте. Разведи их так, чтобы
между ними был настоящий зазор по горизонтали, и подъём сразу станет
требовать точности.

### Добавить шип на землю
Впиши номер колонки в `spikeColumns`. Убедись, что эта колонка не внутри
`gaps` — шип в пустоте проверку не пройдёт.

### Сделать ловушку быстрее или медленнее
Найди её `timing` и меняй фазы. Чтобы **чаще срабатывала** — уменьшай
`idleMs`. Чтобы **дольше была опасной** — увеличивай `activeMs`. Чтобы
**резче выскакивала** — уменьшай `warningMs` (но не ниже 250).

### Сдвинуть момент срабатывания внезапной ловушки
В готовых связках — параметр `lead`. Больше число = триггер дальше от
ловушки = игрок получает сигнал раньше.

### Добавить новый уровень
1. Скопируй блок существующего уровня целиком внутри файла сектора.
2. Поменяй `id` на следующий свободный (`sector-03-level-07` работать не
   будет — в секторе ровно 6 уровней; для нового сектора нужен новый файл и
   строка в `LevelFactory.ts`).
3. Поменяй `name` и все `id` ловушек внутри — они должны быть уникальны.
4. `pnpm levels` → убедись, что `solvable`.

### Откатить неудачную правку
```
git diff                 # что изменилось
git checkout -- src/data/levels/sector04.ts   # вернуть файл как было
```

## 11. Частые ошибки

| Симптом | Причина |
|---|---|
| Платформа уехала не туда | `row` растёт вниз — уменьшай, чтобы поднять |
| «Не могу допрыгнуть» | Подъём больше 3 клеток, либо слишком далеко вбок — см. таблицу в разделе 5 |
| Ловушка не срабатывает | Триггер слишком высоко/низко, либо игрок перелетает его. Проще всего — использовать готовые связки из раздела 7 |
| `UNSOLVABLE` | Разрыв в маршруте: яма шире прыжка, платформа недосягаема, выход висит в воздухе |
| Игра не запускается | `pnpm typecheck` — почти всегда опечатка в названии поля |
| Тест про «two hazards» | Две ловушки перекрываются и по колонкам, и по строкам — разведи их |
| Шипы наложились друг на друга | То же самое: проверь колонки соседних ловушек по карте `pnpm levels` |

## 12. Порядок работы

```
1. открыть src/data/levels/sectorNN.ts, найти уровень по name
2. поменять числа
3. pnpm levels     → карта и solvable
4. pnpm test       → правила честности
5. pnpm dev        → поиграть руками
```

Последний шаг обязателен. Проходимость по солверу и «в это приятно играть» —
разные вещи, и вторую не проверит ни одна команда.
