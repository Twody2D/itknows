# Performance Budget

Обновляется после каждой фазы (`pnpm build && pnpm size`). Числа ниже —
фактические измерения, а не оценки.

## Целевые показатели

| Метрика | Цель | Жёсткий потолок ТЗ |
|---|---|---|
| FPS на слабом мобильном устройстве | стабильные 60 | — |
| Размер `dist/` | < 3 МБ | 10–20 МБ (§3 ТЗ) |
| Аллокации в hot path (`update()`) | 0 | — |
| Частицы одновременно на экране | ≤ 150 (авто-снижение на слабых устройствах) | — |

## Стратегия ассетов

- **Текстуры**: генерируются процедурно на offscreen `<canvas>` в `src/art/`
  и регистрируются как Phaser-текстуры в рантайме. Ни одного PNG/JPG в
  репозитории или в билде.
- **Аудио**: синтез через Web Audio (Phase 5). Ни одного MP3/OGG в билде.
- **Шрифты**: bitmap-шрифт из glyph-данных (Phase 4) + системный `monospace`
  fallback для текста, который ещё не переведён на bitmap-рендер. Ни одного
  `.ttf`/`.woff` в билде.
- **Иконки**: инлайн-SVG там, где нужны (например, favicon), без сторонних
  icon-паков.

## Стратегия зависимостей

Единственная runtime-зависимость — `phaser`. Она же — основной вклад в
размер бандла (минифицированный Phaser ≈ 1.4 МБ), и это ожидаемо: весь
игровой код проекта на его фоне пока измеряется килобайтами.

## План по FPS-деградации (заложено архитектурно, реализуется в Phase 7)

При падении FPS ниже целевого на замере — снижать в этом порядке:
1. количество частиц;
2. второстепенные фоновые слои (параллакс, digital rain и т.п.);
3. экранные эффекты (chromatic/glitch, screen shake).

Физика и ввод никогда не деградируют — см. `CLAUDE.md` #9.
